## 后台智能速览

### 启动时机

- “转写后自动生成智能速览”开启后，新录音转写保存成功即进入后台分析队列，不要求用户先打开转写详情。
- 每次启动应用都会扫描历史摘要，把没有智能速览、存在有效转写段落且不是完全失败的记录补入队列。
- 未配置当前 AI Provider 的 API Key，或 Token Plan 尚未确认适用范围时，不创建新的计费任务。
- 关闭自动生成后，自动任务暂停；用户在详情页手动点击生成仍可正常执行。

### 队列规则

- 智能速览严格串行生成，同一时刻只有一个 AI 分析请求，避免多个长上下文请求同时占用额度。
- 任务按 `transcriptId + revision` 去重；同一版本重复打开或重复点击不会创建重复请求。
- 手动任务排在尚未开始的自动任务之前，但不会中断正在执行的请求。
- 队列持久化到用户数据目录的 `pending-analysis-jobs.json`。应用异常退出时，运行中或等待重试的任务会在下次启动恢复为排队状态。
- 429、503、其他 5xx 和网络异常最多自动尝试 3 次，优先遵循 `Retry-After`，否则使用指数退避。
- API Key、Provider 或 Token Plan 确认缺失时标记为阻塞；配置恢复后自动继续。
- 401/403、结构化结果错误等终止错误保留在队列状态中，由用户修正配置后重试，不无限消耗 Token。

### 数据一致性

- 智能速览记录生成时使用的转写 `revision`。
- 如果分析过程中原文被编辑，旧请求结果不会覆盖新正文；队列会基于最新版本重新排队。
- 原文编辑后，已有速览标记为“可能已过期”，由用户选择重新生成。
- 只有完整通过结构校验的新结果才写入历史记录。

### 可视化队列与历史检测

- 底部状态栏始终提供“智能速览队列”入口，同时显示队列总数与正在处理数量。
- 面板合并两类数据：真实后台任务，以及历史摘要中状态为“尚未生成、已过期、生成失败”的记录。
- 真实任务展示排队位置、尝试次数、下次重试时间和脱敏错误；历史检测项明确标注来源，不伪造后台执行状态。
- 已完成速览、完全转写失败或没有有效文字段落的记录不会进入面板；同一转写版本不会重复显示。
- 支持全部、处理中、待生成和异常筛选，以及打开原文、生成、重新生成、重试和移出操作。
- “移出”按 `transcriptId + revision` 持久化为忽略标记。应用重启后不会重新发现同一版本；原文修改产生新 revision 后会再次显示。
- 正在运行的请求不可强制移出，避免把实际仍在消耗额度的工作伪装成已停止；其他等待、失败和历史检测项均可移出。

## 本地音频准备并行

设置提供三种模式：

| 模式 | 行为 |
| --- | --- |
| 顺序准备 | 同时只执行 1 个媒体的 FFprobe、静音检测、音轨提取和切片 |
| 自定义并行 | 用户填写任意正整数；默认 3，不再限制为 1–4 |
| 无限制 | 当前批次所有等待中的媒体均可开始本地准备，不设置应用级数量上限 |

无论本地准备模式为何，媒体之间的 API 转写通道始终为 1：音频 1、2、3 可以同时完成本地切片，但必须按入队顺序依次进入 API 转写。单个媒体内部仍使用既有 RPM 和自适应切片请求调度。

“无限制”只表示没有应用级并行数量上限，不代表系统资源无限。启用前界面会确认并警告 CPU、内存和临时磁盘占用；系统无法创建进程或磁盘不足时，对应准备任务会安全失败，不会改变其他已完成结果。

旧设置自动迁移：

- 旧“并行准备”关闭 → 顺序准备。
- 旧“并行准备”开启或未记录 → 自定义并行。
- 原有并行数继续保留；非法值回退为 3。
